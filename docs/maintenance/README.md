# Fork 维护记录

本目录记录本地定制和官方同步的维护决策。代码和精确差异以 Git 为准；文档说明修改原因、保留理由、兼容影响和验证证据。

- [本地定制变更台账](local-changes.md)：按发生时间记录定制，标识当前是否保留。
- [官方同步历史](upstream-sync-history.md)：每次同步的官方基线、本地基线、结果提交与验证索引。
- [2026-11-23 同步详情](2026-11-23-upstream-sync.md)：本次官方更新、重叠判断、冲突处理及兼容变化。

## 后续维护约定

1. 修改本地行为时，在本地台账新增记录：日期、提交、原因、涉及模块、验证、当前状态。被官方替代时保留原记录，标记替代提交和同步记录。
2. 每次同步先获取官方 main 并固定 SHA，确认工作区状态；记录共同祖先和双方独有提交数，不以文件行数判断工作量。
3. 在独立分支 merge 官方 SHA，逐项审查本地定制；补丁等价检查只证明代码补丁是否相同，不能代替功能与测试审查。
4. 为每次同步新增 YYYY-MM-DD-upstream-sync.md，记录基线、更新摘要、冲突与非冲突适配、兼容影响、测试环境及结果。一天多次同步时文件名增加序号。
5. 合并完成后更新同步历史，填入最终合并 SHA。区分“同步分支已合并”“main 已集成”“已推送”“已发布”；不能将离线测试通过等同于生产验证。
6. 不依赖临时目录保存唯一证据；文档保留可重跑命令、结果和关键依赖版本。需要复现单次测试环境时保存该环境的依赖快照。

新增记录随对应代码提交，补录记录应明确标注；本目录不要求为了更新文字单独运行产品测试。
